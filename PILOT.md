# Paid Pilot Structure

This document describes a practical starting point for an IBRAMIND InfraRisk paid pilot.

## Example pilot scope

- One infrastructure project or a small project portfolio
- Agreed evidence sources such as site diaries, schedule notes, QA/QC records, commercial notes, or risk registers
- Defined risk categories and escalation rules
- Private deployment or controlled test environment
- Human review and acceptance workflow
- Final findings pack and pilot evaluation summary

## Acceptance criteria

A pilot should be judged against agreed, observable criteria such as:

- Evidence traceability
- Structured-output validity
- Invalid-citation rate
- Reviewer usefulness
- Workflow completion
- Response consistency
- Security and data-handling requirements
- Integration feasibility

The public benchmark in this repository measures runtime/provenance properties only and is not a substitute for project-specific engineering validation.

## Commercial boundary

The public repository remains a demonstrator. Enterprise integrations, organization-specific rules, production deployment, support, governance, and private IBRAMIND platform capabilities are delivered separately.
